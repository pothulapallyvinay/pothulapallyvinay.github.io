FAQ

Frequently asked questions about website launches

Common technical launch questions - answered without the fluff.

How far in advance should I start this checklist before my launch date?
Begin the Architecture and Technical SEO phase (Phase 1) at least 14 business days before the target launch. Phases 2 and 3 run concurrently and need 7–10 days. Security and compliance (Phase 4) should be locked 5 days out to allow certificate propagation and header testing. Analytics verification (Phase 5) requires 48–72 hours of live data collection after deployment to confirm data integrity. Compressing this timeline increases the probability of shipping broken redirects, missing tracking, or failing Core Web Vitals in the 28-day CrUX assessment window.
What is the single most damaging mistake teams make at launch?
Failing to implement a complete 301 redirect map from the old URL structure to the new one. Every indexed URL that returns a 404 instead of a 301 bleeds accumulated PageRank, drops existing keyword rankings, and generates soft-404 errors in Search Console. For sites with 500+ indexed pages, this can result in a 30–60% organic traffic loss within the first two weeks post-launch. Always crawl the production site with Screaming Frog or Sitebulb before DNS cutover and map every legacy URL.
Do I need to re-submit my sitemap after launch?
Yes. Even if your sitemap URL hasn't changed, resubmit it in both Google Search Console and Bing Webmaster Tools immediately after launch. This signals to crawlers that the site structure has been updated and accelerates re-indexing. Additionally, use the URL Inspection tool to request indexing for your highest-priority landing pages manually. Monitor the Coverage report daily for the first week to catch unexpected "Excluded" or "Error" statuses.
How do I verify my Core Web Vitals won't fail after launch?
Run Lighthouse CI in your deployment pipeline against the production build (not localhost) to catch regressions before they reach users. After launch, monitor the Core Web Vitals report in Search Console - but understand this data is based on a 28-day rolling average from CrUX, so field data won't reflect your new site immediately. In the interim, use PageSpeed Insights (lab data) and web-vitals.js (real-user monitoring piped to GA4) to get immediate signal. Target LCP under 2.5s, CLS under 0.1, and INP under 200ms at the 75th percentile.
